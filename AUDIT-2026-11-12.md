## A. Test and tooling problems (fix first, everything else depends on them)

### A1. Default `python3` on this Mac cannot install the pipeline dependencies
- `python3` is 3.15.2. `pip install -r requirements.txt` fails building `scikit-image`, so `numpy` is missing.
  Consequences seen today: `test_pipeline_gorst` import error, `test_t1_f10_03_turnaround_loops_retained` and
  `test_t1_f11_04_check_repair_passes` fail, `tools/check_repair.py` crashes.
- `/opt/homebrew/bin/python3.14` (3.14.6) installs everything fine. CI uses 3.12.
- Fix: create `.venv` (already git-ignored) with Python 3.14 or 3.12, install requirements, and document the
  exact command in `CLAUDE.md` "Run, build, test, ship". Optionally add a `.python-version` or a version check
  at the top of `pipeline/build_all.py` that says "use Python 3.12 to 3.14".
- Done when: `python -m unittest discover -s tools -p 'test_*.py'` passes from a fresh clone using the documented steps.

### A2. Playwright does not run with the installed browser
- `playwright` is not resolvable from Node (`require('playwright')` fails with the default `NODE_PATH`).
- `~/Library/Caches/ms-playwright` holds `chromium-1134` and `chromium_headless_shell-1254`. A package whose
  expected build number differs (1.57 expects 1200) will not find either. Launching the cached 1254 headless shell
  by `executablePath` works (Chromium 158).
- Several sessions today reported "Chromium won't launch" or "Playwright isn't installed" and skipped `sweep.js`
  because of this. Ask the user before installing, then either `npx playwright install chromium` for a
  package version that matches, or install the playwright version whose revision is 1254.
- Done when: `node tools/sweep.js` runs from the repo root following instructions written in `CLAUDE.md`
  (add a macOS note next to the existing "preinstalled in the cloud sandbox" line).

### A3. CI never runs any browser test
- `.github/workflows/checks.yml` runs: `py_compile`, Python unittests, `node --check`, `geometry_check`, `ribbon_check`,
  `test_routing_engine`, `stress_test_routing`, `validate_data`, `check_repair`, and a keyless build.
  It does **not** run `sweep.js` or any of the `tools/test_*.js` UI/source tests. Every UI regression is caught
  only if a session happens to run them locally, which A2 prevented today.
- Proposed: add a job that installs Playwright's Chromium, serves `site/` and runs `tools/sweep.js`
  (blocking tile requests as the tests already do), plus the `tools/test_*.js` files that are plain Node source checks
  (after A4). The user should confirm adding CI minutes; the change is small.
- Done when: a deliberate UI break on a throwaway branch fails the `Check map` workflow.
