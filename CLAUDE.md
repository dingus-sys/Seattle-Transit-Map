# King County Transit Map: notes for Claude sessions

Read this first, then `README.md` (how the map is built and what each file does). This file is
the working context: how to run, test and ship changes, the rules to follow, what was learned
the hard way, and what is still open.

## What this is

An interactive map of every transit service in the Puget Sound region (Everett to Olympia,
plus Kitsap and Vashon): Link, Sounder, streetcars, monorail, RapidRide, Swift, all-day and
rush-hour buses, DART and Flex on-demand areas, and ferries, with live vehicles and service
alerts. It is drawn in the manner of the printed Seattle Transit Map: each street with
service is a corridor, lines follow the real streets, and the look is Apple "liquid glass".

- Website (GitHub Pages): https://dingus-sys.github.io/Seattle-Transit-Map/
- Repo: https://github.com/dingus-sys/Seattle-Transit-Map. `main` is what gets deployed.
- Preview on claude.ai (a private artifact, no live data): https://claude.ai/artifact/BXhkuKv6UQXFmkgiyYz7BA
  Update it with the Artifact tool, passing that URL. `site/artifact.html` is generated by
  `build_site.py` and git-ignored. When `site/data/*.json` change, publish those files too
  (`files: {"data/network.json": "site/data/network.json"}`); a plain page publish doesn't send them.

## Rules (do not break)

1. **Never commit an API key.** The OneBusAway key and the WSDOT ferry access code live in the
   GitHub secrets/variables `OBA_API_KEY`, `WSP_KEY` (ferries), `WSDOT_KEY` (roads), or `WSF_ACCESS_CODE`, in the environment variables of
   the same names, or in `pipeline/local_secrets.json` (git-ignored:
   `{"oba_api_key": "...", "wsf_access_code": "..."}`). The page (`site/index.html`, `app.js`,
   `app.css`, `geom.js`) is not in the repo: the Pages workflow builds it with `build_site.py`, which
   writes placeholders by default. The Pages workflow passes secrets through the environment
   and builds with `--with-key`, using JSON escaping rather than shell substitution.
   - Test live data with `python3 pipeline/build_site.py --with-key`, then rebuild without
     `--with-key` when you're done.
   - Before every commit: `git grep --cached -F "<the key>"` finds nothing. Don't paste keys into
     chat or print them.
2. **Don't hand-edit `site/data/*.json`.** The weekly workflow (`refresh-data.yml`, Mondays) rebuilds
   them from scratch and overwrites the repo. Fix problems in `pipeline/` or `web/`.
3. **Don't use official agency logos** (RapidRide, Link, DART and the rest are trademarks, and it
   would make the map look like an official agency product). Original symbols for service types are fine.
4. **Other sessions and the weekly data bot push to `main` too.** Before pushing run `git fetch origin`
   and rebase on `origin/main` (`git rebase origin/main`); never force-push. Look at
   `git log --oneline origin/main` first: someone may have just changed the same area. Read their
   commit messages, which explain the why.
5. Follow the attribution lines your session instructions give for commits and PRs.

## Run, build, test, ship

```bash
pip install -r requirements.txt
python3 pipeline/build_site.py                 # after editing web/*: rebuilds the page in site/ (fast)
python3 pipeline/build_all.py --no-tiles       # rebuilds all data (slow: downloads GTFS and tiles into <repo>/.cache,
                                               #   or $TRANSIT_CACHE; delete .cache/gtfs to force a fresh download)
python3 -m http.server -d site 8765 &          # serve it (a background server dies after its time limit)
```

The data under `site/data/` is committed, so UI work never needs `build_all.py`. A change to
`pipeline/` does: run it, look at the result, and commit the regenerated `site/`.

**Tests** are Playwright scripts in `tools/` (Playwright is preinstalled in the cloud sandbox).
Run them from the repo root with the site served on :8765:

```bash
export NODE_PATH=$(npm root -g)               # if the sandbox can't reach the CDN for maplibre-gl.js,
export MAPLIBRE_JS=/path/to/maplibre-gl.js    #   set this to a local copy
node tools/sweep.js                           # 51 checks: expect "51/51 passed"
node tools/close.js '[["name",[-122.3365,47.6085],16]]'   # screenshot views to shots/c-name.png
node tools/bench.js                           # layout time per zoom (worker 5-260 ms is normal)
node tools/zoomgap2.js tag                    # pinch-zoom check (lines must stay together)
node tools/strandorder.js                     # strand swaps at junctions (42 in the November 5 network)
node tools/geometry_check.js                  # all routes/zoom levels, selection/hover agreement
python3 tools/check_repair.py                 # omitted branches, anchored repairs, direction metadata
node tools/deployed_watch.js https://dingus-sys.github.io/Seattle-Transit-Map/   # live data on the real site
python3 tools/near.py -122.15 47.58 250       # network segments near a point
```

Tile requests to openfreemap are blocked in the tests on purpose, so they use the bundled tiles.
Test hooks: `window.__map` (MapLibre) and `window.__atlas` (`rebuild`, `idle()`, `lastFeats()`,
`liveState()`, `alerts()`, `wsfState()`, `engineInit`, `lastParams`).

**The loop that has worked every round:** change code, rebuild, take screenshots of the exact
places in question (and a few other busy places, to catch side effects) and look at them, run
`sweep.js`, rebuild keyless, check for keys, commit, push to `main`, wait for the deploy
(`gh run list --limit 1`), check the live site, republish the artifact, and send the user the
screenshots that show the change. In the sandbox `gh run list` works, but `gh` can't read
secrets or the Pages API (the proxy blocks them); check the live page with `curl`.

## How it works (short)

**Pipeline** (`pipeline/`, run in this order by `build_all.py`): `build_basemap` (tiles and fonts)
then `process_gtfs` (routes, stops, schedules) then `build_areas` (DART, Access, Flex) then
`match_shapes` (snaps every bus and streetcar shape onto the real street network with an HMM)
then `build_graph` (the shared-corridor network, `site/data/network.json`) then `tidy_junctions`,
`repair_network` (remaining source-path omissions and 2 m simplification), then `build_site`.
- `network.json`: `{lines: [route ids], edges: [{c: [[lon,lat]...], l: [line indexes], d: [direction per line]}]}`.
  Three separate layers: surface, rail, water.
- `tidy_junctions.py` (idempotent, repeats until nothing changes) fixes what tracing leaves behind:
  a crossing traced as two junctions (routes jog or hop into the other line's bundle), knotted
  freeway interchanges, a bundle bent into a junction that sits on a street beside it, and
  dead-end route stubs. Thresholds are constants at the top of the file.
- `config.py`: `REGION` (map area), `FEEDS`, live settings. Rebuilding for a new region is one edit.

**Browser** (`web/`; `build_site.py` copies it into `site/` as `index.html` beside `app.js`, `app.css`
and `geom.js`, each linked with a content hash `?v=` so browsers cache them, and inlines it all into
one file for the artifact):
- `geom.js` is the line engine. It runs in a Web Worker started from `geom.js` (`<script id="geom-src">`;
  in the one-file artifact, from that script's inline text). `?noworker` forces it onto the page. It turns the network into what one view draws: each route is a
  continuous strand; a street's line gets wider with the number of routes on it (about 1x, 2x, then
  slowly more); strands touch; where a route turns off its strand peels away; lanes are kept through
  junctions by sliding whole bundles sideways; strands are ordered to minimize swaps. The 1 and 2 Lines
  on shared track are one line, green and blue halves. Boats are one line per crossing.
- `app.js` has the MapLibre layers (street stack, then the rail stack on top, each with shadow,
  casing and line; strand dividers; places; stops; vehicles), hover and click, tags, the panel, live
  vehicles, alerts and the settings.
- Widths are in "line units" and converted to pixels per feature using its `zu` (the zoom its
  layout was made for), so lines stay together while zooming. Layout is re-run continuously as
  you pinch (`z`, steps of 0.02); simplified shapes and tag spacing use the quarter step `zs`.
- Hover: `pickLine` finds the route strand under the pointer (sticky: the current target is held
  until the pointer is clearly off it); the route's whole path is drawn bold in one of two
  cross-fading hover layers; the tooltip glides, morphs between cards and fades.

**Live data:** vehicle positions and service alerts from OneBusAway Puget Sound (GTFS-realtime,
decoded by hand in `app.js`; agencies in `OBA_AGENCIES`), Intercity Transit's own feeds, and
Washington State Ferries boats from OneBusAway's REST feed (the realtime feed lacks the route).
Each polling round starts at a different agency, and a rate-limit answer skips the rest of
OneBusAway that round. Vehicles also carry how busy they are (occupancy, read from both the
realtime feed and the REST status), and a stop card first shows the timetable, then swaps in the
agency's predicted departures (OneBusAway `arrivals-and-departures-for-stop`, one stop at a time, cached
30 s, with its own rate-limit pause); stop ids map to OneBusAway's by feed (`stopAgency` in `ATLAS_LIVE`). The WSF API (ferry bulletins, "at the dock / arrives about") needs the
WSDOT access code and is called with JSONP. Places (parks, schools, museums, zoo...) come from
the map tiles; the bundled tiles keep only named places of the kinds in `POI_KEEP`
(`build_basemap.py`). Highway shields work from the bundled tiles too.

## Gotchas

- `MPP0` in `geom.js` is 78271.5 × cos(lat) because MapLibre's world is 512 px wide at zoom 0.
  An earlier value twice as big made lanes sit twice as far apart as the lines were wide.
  Don't "fix" it.
- Never use a shell `pkill -f` pattern that can match its own shell (it exited with 144).
- A screenshot from the user may be from before the last deploy: check which version it shows
  before chasing a bug that is already fixed.
- The `route`/`line` filters, tags and layers read feature properties set in `geom.js`
  (`r, cat, e, zu, wm, cm, hm, sh, ws, n, g, c, s, d, h, ar`); change both sides together.
- After a pipeline run, check the `match_shapes` line: it should match about 667 of 680 shapes.
  If it says `{'error': N}` the street matching failed and the network is built from rough agency
  shapes (routes break on bridges). It used to fail on macOS/Python 3.14 (worker processes that
  weren't forked); it now forks, but check the count.
- Route QA: compare what's drawn with each route's real path and stops before shipping a data
  change. A good check: for every route, its matched shape (`.cache/route_shapes_matched.json`)
  should stay within ~60 m of its drawn edges, its edges should be one connected piece, and its
  stops within ~80 m. Routes folded onto the next street over (one-way pairs) are expected to
  show up to ~130 m off.
- Trains: a line goes on a stretch of track when it covers 70% of it, so a line that ends partway
  along a long stretch needs a junction there (`split_at_line_ends` in `build_graph.py`), or it is
  drawn past its end (Sounder N) or not at all (Sounder S to Lakewood).

## Working with this user

- They write quickly and casually, with typos; read for intent, and look at the screenshots they attach.
- They want it to look like the printed Seattle Transit Map (clean corridors, wide where routes share a
  street, no weird angles) and to feel smooth and luxurious: no flicker, easing, fade and pop.
- They notice when a fix is a one-off. Fix the class of problem (find all the places it happens), and
  check several other places afterwards.
- Always show before and after screenshots of what changed; send them the relevant ones.
- Ship each round: commit, push `main`, confirm the deploy, republish the artifact, then summarize
  what changed and what's still open, in plain language and without jargon.
